# 林农收益分配账领域约定

本项目面向集体林权改革与林下产业协作场景：九十万亩林地陆续流转后，村集体要把
**保底租金、经营分成、务工收入、生态奖励**四类收益分别结算到户。年终选取跨两个
项目的一户回放时，每一笔到账、冻结、追补都必须能还原计算依据，且总账平衡。

## 一、核心原则：只追加分录，总额靠投影

任何已入账记录都不可修改或删除。暂缓、冻结、解冻、追回、追补、纠错全部是**新增
分录**。所有余额（资金账、到户应付、冻结/暂缓额度）都由分录序列投影得到，可随时
完整重放：

- 每条分录含 `seq`、`prevHash`、`entryHash`（SHA-256，覆盖前链与全部业务字段及
  结构化计算依据快照）。改动旧账的任何一个字段，链即断裂，`verify()` / 启动重放会
  直接拒绝。
- 会计恒等式（每次核验强制检查）：
  - 资金账 = 回款 − 支付（红字追回为负支付，现金退回集体账）
  - 到户应付净额 = 计提 + 更正 − 支付
  - 应付净额 = 可付额 + 冻结额 + 暂缓额

金额一律用整数“分”，面积用整数“毫亩”（三位小数亩），跨户分摊用**最大余数法**
保证各户之和恒等于总额、尾差自动配平；面积·份额·天权重用 BigInt，九十万亩×365 天
也不丢精度。

## 二、四类收益如何生成应付分录

| 来源 | 计提方式 | 幂等域 |
| --- | --- | --- |
| 保底租金 RENT | 年标准 × 面积 × 权属份额 × 有效天数 ÷ 全年天数，按权属版本切段按日分摊 | `来源:期间:地块:户` |
| 生态奖励 ECO_REWARD | 同上 | 同上 |
| 经营分成 DIVIDEND | 项目回款批次到账后，按期间“面积×份额×天数”权重把批次总额分摊到户；同批可多次分发 | `回款分录:批次号:户` |
| 务工收入 WAGE | 一条务工记录一笔计提 | 务工记录号 |

- 权属按**有效期版本**管理（`[from, to)` 左闭右开），份额以万分比表示。年中流转、
  继承、争议裁决都只切新版本，旧版本保留，旧账仍能按当时的权属还原。
- 同一务工记录重传命中幂等键，返回原分录，不重复计提。
- 回款先入集体资金账（RECEIPT），分成与兑付受资金账余额约束；资金不足时按批次
  **部分支付**，未付部分继续挂账，总账以 `cashShortfallCents` 标明等回款的缺口。

## 三、跨期场景全部走追加分录

1. **回款分批 / 延迟**：对应应付可做 SUSPEND（暂缓，注明 `RECEIPT_DELAY`），后续
   回款到账后 RESUME 再支付；也可不暂缓直接等回款，部分支付自动处理。回款晚到次年
   但归属期间**尚未关账**时，以 `basis.lateBooking` 迟到记账追入旧期；**关账后**才
   只能走 `post_close` 更正。
2. **成员去世、继承待定**：FREEZE 冻结该户全部可付挂账（注明
   `INHERITANCE_PENDING`），继承明确后 RELEASE 解冻；冻结额不可支付、不可超额解冻。
3. **地块份额争议**：争议批次 SUSPEND（`SHARE_DISPUTE`）；裁决后登记侧切权属版本，
   账本侧以 CORRECTION 追加分录重算。
4. **结算后权属更正**：期间关账（CLOSE_PERIOD 本身也是链上分录）后，日常分录一律
   拒绝；更正只能以 `tag=post_close` 的 CORRECTION 追加，按更正后权属有效期重算，
   差额带符号（追补为正、转出为负）。已多付的户须先以**红字支付**追回，再做更正；
   更正在提交前逐户预演余额约束（两阶段提交），杜绝负应付和半截更正。
5. **分成批次重算**：争议裁决后按新权属重分既有回款批次，批次总额守恒。

每条调整分录都在 `basis` 中保留结构化计算依据（分段天数、面积、份额、权重、公式、
关联原分录、事由、经办人），回放单逐笔展示并给出全户指纹。

## 四、查看范围遵循村组权限

- `admin`：跨村组，可回款、年度计提、项目级批量暂缓、关账、更正；
- `manager`：限本组读写，可登记务工、兑付、冻结/解冻本组户；
- `viewer`：限本组只读。
- 非 admin 的总账与清单只汇总其村组范围内的到户分录；跨组查询回放单返回 403。

## 五、按户可核验明细（回放单）

`buildHouseholdStatement` 按户、按应付批次组织时间线，列出每笔计提/支付/冻结/解冻/
暂缓/恢复/追补的金额、原因、经办人、关联分录、计算依据与分录哈希，并按来源汇总。
回放单附带：账本恒等式核验结果、哈希链头、本户明细 SHA-256 指纹（重复出具结果
一致，任一旧账被改指纹即变）。

## 六、模块结构

```
src/domain/
  catalog.mjs    来源、分录类型、挂账原因、角色常量
  money.mjs      定点金额/面积、最大余数法、BigInt 四舍五入
  time.mjs       日期、结算期、区间重叠天数
  hash.mjs       SHA-256 与规范序列化
  id.mjs         确定性标识
  registry.mjs   村组/项目/农户/成员/地块/权属有效期版本（快照可重建）
  journal.mjs    只追加分录账：哈希链、余额投影、关账、重放核验、快照装载
  ledger.mjs     门面：四类来源计提、到户操作、暂缓/冻结、更正两阶段提交
  statement.mjs  按户可核验回放单
  access.mjs     村组权限策略
src/app/
  service.mjs    应用服务（门面 + 权限 + 范围化查询）
  http.mjs       HTTP 适配（POST /api/commands；GET 查询）
  store.mjs      JSON 原子持久化与启动哈希链重放
src/server.mjs   启动装配
test/            15 个测试：领域场景、权属版本、权限、持久化、防篡改、HTTP
```

业务记录区分来源、发生时间与当前有效版本；涉及个人、机构或敏感地点的信息只向职责
范围内的角色开放；所有对外结果都能追溯到采用的数据版本（分录哈希与回放单指纹）。
