# 林农收益分配账领域约定

项目面向集体林权改革与林下产业协作场景。九十万亩林地陆续流转后，村集体需要把
**保底租金、经营分成、务工收入、生态奖励**四类收益，按权属有效期分别结算到户；
年终要选取跨项目的户回放，每笔到账、冻结、追补都能还原计算依据，且总账平衡。

## 核心原则

1. **分录只追加，旧账不改写。** 一切变化（暂缓、追补、解冻、纠错、追偿、退回）
   都以新凭证体现；纠错采用“红冲（原凭证全额负数冲回）+ 蓝补（按更正后依据重新
   计提）”，原凭证永久保留并带 `reversedBy` 指向红冲凭证号。
2. **复式记账，每张凭证借贷相等。** 五个科目：
   - 现金池：项目回款进账借记、发放/退回贷记；
   - 项目收益清算：项目级，回款贷记、计提借记（保证“有回款才计提”）；
   - 应付收益款：已计提待付，贷记计提、借记发放/暂缓；
   - 冻结待付：地块争议、继承待定期间暂缓的资金；
   - 应追回款：结算后权属更正形成的超付债权，退回时冲减。
3. **金额一律为整数“分”**，杜绝浮点误差；按权重分金用最大余数法，零头补给余数
   最大的一户，保证 Σ分配额 分毫不差。
4. **凭证哈希链**：每张凭证含前一张凭证哈希（SHA-256），任何事后篡改都会在
   `verifyChain()` 被定位。

## 计提引擎：权属有效期 × 收益来源 × 已回款批次

- 权属以**版本链**管理：每版有生效区间（半开 `[validFrom, validTo)`），新版本切片
  旧版本有效期；结算后追溯更正通过插入“追补版本”完成，旧版本仍可查。
- 份额用百万分率（ppm）表示，和必须为 1,000,000。
- 地块类来源（保底租金、经营分成、生态奖励）：把结算期按权属版本、争议窗口、成员
  生死/继承确定日切成段，每段权重 = 份额ppm × 天数；计提金额按批次回款额 × 权重
  分摊，每段依据（区间、天数、ppm、是否冻结）随凭证留存。
- 务工来源：按人登记务工记录，**记录号全局幂等，重传拒绝**（返回 `duplicated`），
  金额本身即权重；更正只能走追加分录。
- 回款分批入账，批次号在事件内幂等；**晚于约定到账日的批次生成“追补”凭证**。
- 截至计提时点尚未解决的争议或继承待定，对应份额先计提应付、随即暂缓冻结；
  争议解决/继承确定后解冻。继承可跨户，解冻凭证贷记继承人所在户。

## 结算后权属更正

`correctShares()` 只追加凭证，顺序为：

1. 插入追补权属版本（追溯生效，旧版本切片保留）；
2. 已解冻的跨户冻结款联动红冲解冻凭证；
3. 对每个受影响批次：红冲原计提与其联动暂缓 → 按新版本链蓝补（蓝补时仍待定的
   份额继续冻结，继承已确定的份额计到继承人名下）；
4. 按**受更正事件流水**轧差：已付多于新应付的成员，差额转“应追回款”；少付的留待
   补付。支持对同一批次反复更正（每次红冲现行蓝补再蓝补）。

## 按户对账恒等式

```
净计提（含红冲/蓝补） + 跨户解冻转入
  = 已到账净额（发放 − 多领退回） + 应付余额 + 冻结在账 + 跨户解冻转出
```

`reconcileHousehold()` 同时披露应追回款余额；`householdStatement()` 出具逐笔
可核验明细（含计算依据快照与各科目滚动余额），末尾附恒等式、总账平衡与哈希链
结论。

## 查看权限（村组范围）

- `{scope:'admin'}`：经管人员，全域可见；
- `{scope:'group', groupId}`：村组，仅本组户；
- `{scope:'household', householdId}`：农户，仅本户。

涉及个人与敏感地块的信息只向职责范围内的角色开放，所有对外结果都可追溯到采用的
数据版本（凭证哈希链 + 权属版本号 + 事件/批次号）。
